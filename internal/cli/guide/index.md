# Canon agent guide

Canon is a typed configuration language. `canon` reads `.canon` sources (and JSON, CSV, C
headers and text through `load`), checks every value once at build time, then writes typed Go
and C++ code, JSON data files and a studio view model. Runtimes never run Canon: they read
values that are already valid. A project is the directory holding `project.canon`.

## The three laws

1. Pure: no clock, randomness, network or environment. The only inputs are files under the
   project or its declared roots, read by `load`. Same sources, same output bytes.
2. Build-time only: functions, checks and loops run in the compiler; generated code holds types,
   values, lookups and getters, plus translated `export fn` bodies that take runtime inputs.
3. Always finishes: evaluation runs under a step budget (`E4401` when spent).

## Topics: `canon guide <topic>`

| Topic | Content |
|---|---|
| `syntax` | files, packages, imports, comments, literals, naming, canonical layout |
| `types` | scalars, refinements, enums, records, variants, optionals, collections, refs, dependent types |
| `data` | `let`/`const`, tables, `entry` files, `load`, `@json` wire names, stable ids and `canon.lock` |
| `logic` | functions, methods, expressions, `match`, standard library, checks, tests |
| `emit` | `emit` targets and modes, what is generated, `export fn` |
| `views-i18n` | views, the studio package, translation files |
| `layers` | `amend`, layer files, `--layer`, runtime `input` fields |
| `cli` | commands, value paths, the JSON of `check`, `explain`, `refs`, `edit`, `rename` |
| `errors` | reading a finding, common codes, edit refusals |
| `recipes` | command sequences for the common tasks |

## The fix loop

```sh
canon check --format json                # 1. findings: code, file:line:col, package, path
canon explain 'pkg:path' --format json   # 2. a value, its type, where each part was set
canon refs 'pkg:path'                    # 3. who uses an entry, before removing or retiring it
canon edit req.json                      # 4a. wrong data: checked, atomic, minimal writes
canon rename <name> <new-name>           # 4b. rename a field, type, fn, let or local everywhere
canon fmt                                # 5. after any hand edit of code
canon check                              # 6. repeat until 0 errors; canon test runs tests
```

- Data (values, in `.canon` literals or loaded JSON) changes through `canon edit`, at the edit
  path `"<package>:<path>"` of a finding. A finding without `path` is static: fix the code by
  hand, then `canon fmt`. Names change through `canon rename`. Both refuse an edit that leaves
  an error, and print an `undo` request: keep it until the result is checked.
- Never edit a generated file (first line `Code generated by canon` or `GENERATED by canon`,
  or a JSON file with a `$schema` key): change the source and run `canon build`.
- Do not edit `canon.lock`: `canon build` and `canon edit` append to it; only a reviewed
  human edit may bring a retired id back.
