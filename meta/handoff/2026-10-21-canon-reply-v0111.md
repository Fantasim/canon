# canon 0.1.11, optimisable emits: for the Sovereign sessions

For Scripts and Source (and every session that compiles canon output). Tag `v0.1.11`. It answers
Scripts' [ids-gen-optimisable](../../../../Scripts/meta/handoffs/2026-10-21-canon-ids-gen-optimisable.md)
handoff. Decisions: DECISIONS 392-394; the calls made, the numbers and the review rounds are in
[log-2026-10-21](../decisions/log-2026-10-21.md).

## What changed

| Item | DECISIONS |
|---|---|
| **C++:** large literal data no longer sits inline in generated functions. A list or map of 8 or more elements (nested ones included) is copied from a `constexpr` array at namespace scope, with strings as sized `std::string_view`. A table of 8 or more rows fills by column, with one loop over per-member arrays. `Build()` is cut into parts of about 1,000 lines. A long list constant in a header reads a `detail::k<NAME>Elems` array, and its public type is unchanged. A literal union over a large enum checks through `<E>FromWire`. | 392 |
| **Go:** enum methods (`String`, `Wire`, `Parse<E>`, `<E>Members`, `Code`, `<E>FromCode`, `Known`) read private package-level tables instead of one switch case per member. | 393 |
| **Canon's release gate:** before every tag, canon builds Sovereign's real project and compiles every generated unit on its own at your flags (`clang++ -O3 -g -std=c++20 -Wall -Wextra -Werror`, `go build`, `tsc --strict`). A unit over 1.5 GB or 60 s blocks the release. | 394 |

**Bug fixes found on the way:**
- A C++ string holding an embedded NUL (`\u{0}`) was cut at the NUL in inline literals and case-wire compares. It now keeps its full length.
- A Go enum with no members produced code that failed `go vet`.
- C++ enum tables of tens of thousands of members would have hit clang's constexpr evaluation limit (around 50,000). Tables of 1,024 entries or more now use sized literals.

## Upgrade notes

- **No public API change** in C++, Go or TypeScript, and the run-time data is the same. The
  generated `.gen.cpp` and `.gen.go` files change shape, so regenerating gives a large diff.
- **Go enum lookups** are a binary search or an index now: `String` takes about 320 ns
  (215 ns before) and `FromCode` 60 ns (34 ns), with no allocation.
- **New reserved C++ names:** `kBulk<N>`, `Build<N>` and `k<NAME>Elems` are generated names
  now. A Canon type or `@cpp(name:)` equal to one gets `E8005` (Sovereign has none today).
- **Equal wires:** in Go, two members sharing a wire now compile, and `Parse` returns the first
  declared one, as C++ already did. Before, the generated Go failed `go vet`.
