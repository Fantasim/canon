## For Scripts: `canon lsp` memory (F1)

**Cause.** The server never released a project. `didClose` dropped the buffer but kept the
whole project (snapshot, kept analysis, caches, evaluator memo) for the life of the process, so
a window grew by one full project per project it ever visited. At Resource's scale that is about
670 MiB live per project. Editing inside one project was bounded before and after.

**Fix (DECISIONS 368).** A project lives while one of its files is open. When its last open file
closes, the server releases it and clears its findings; reopening a file opens it anew. After 5 s
with no change it returns freed memory to the OS once.

**Measured bound** (synthetic project shaped like Resource: 80 packages, 4,962 files, ~690k
lines; hundreds of edits, each forcing a full re-check):

| | Live heap | RSS |
|---|---|---|
| After N edits, one project | ≤ 1.05 × after the first full check | idle ≤ 1.1 × (peaks ~1.8 × during a pass) |
| Visiting 3 projects in turn | before: 673 → 1346 → 2019 MiB; after: 2.2 MiB once each is closed | before: 1.5 → 2.9 → 4.0 GB held; after: ~60 MiB |

One project the size of Resource idles at about 0.9 GB with peaks near 1.6 GB. Not measured: a
real editor on the real Resource tree over a working day (the brief's acceptance); please
re-measure the gate after the bump.

## Upgrade notes: what the new `canon` may report or change

- **`canon check` reports `E8152`** (two packages claiming one output) where only `build` did.
- **A file with no `package` line** now counts against the package its directory names: scoped
  commands of other packages stop failing on it; `canon check <that dir>` reports it.
- **`compiler:` pin.** Add `compiler: "0.1.6"` to `project.canon` to pin the toolchain: another
  version is `E1015` (Open still works); a local unstamped build is `W1016` and now reports itself
  as `dev`, not `0.1.0`.
- **Stray generated files:** `build --check` reports `E8029` (a plain build `W8030`) for a file
  carrying the generated marker in an emit directory that no emit of the project writes. Delete
  them; canon never does.
- **Writer locks:** builds, `fmt` and edits of one package now wait for each other and print one
  line saying whom they wait for. A source changed under the lock makes the build redo once, then
  fail with `ErrStale` (exit 1). Lock files live in `.canon/writers/` and are never deleted: keep
  `.canon/` out of version control (it also holds the edit journal).
- **API (Go):** `SetOverlay(ctx, file, content)` and `ClearOverlay(ctx, file)` take a context
  (no caller outside canon used them). `ProjectInfo` now holds a slice, so `==` on it no longer
  compiles.
- **Generated decoders' texts:** Go types decoders say `duplicate key` (was `repeated key`) and
  `<T>: invalid JSON at byte N` (was `<T>: $: invalid JSON`); TS data loaders now print
  `<file>.json: rows[0].x: …` like Go and C++ (was a JSON pointer `/rows/0/x`). A TS literal union
  now refuses a value outside its members, as Go always did.
- **Go types mode, two tables of one record:** they share one `type XID string` (only programs
  refused before change).
- **New findings that may appear:** `E8004 consumerCopy` (a copy importing another consumer root's
  only copy), `E8019 OpenEnumFn`, `E8005 finder`.

## Port items D3 and D9 (2026-10-07), answered

- **D3.** `@json(none: …)` on an optional ref no longer reproduces (WIRE §5.4's own example
  passes). Per-field `@json(codes)` is F20, designed, not yet shipped.
- **D9.** `@files` placing an entry by a display name is by design: a placeholder is the field's
  wire form (API.md N2). A naming map would be a second spelling (DECISIONS 319).
