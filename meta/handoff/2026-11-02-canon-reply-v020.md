Also fixed, with no number of their own (each ruled in log-2026-11-01):

- `.id` or `.retired` of a record that is not an entry of a table or keyed list is **`E4003`**, an
  evaluation error at the selection (TYPES §9.3). It crashed the compiler before, and `.retired` read
  `false` silently.
- A const cycle through a record default (`const K = (T {}).a`, `record T { a: Int = K }`) is `E4301`
  at check time. Before, `check` passed and `build` failed with an internal compiler error.
- A bound that builds a record before its body is checked no longer crashes: it gets its own finding
  (`E2102`, `E3204`) or `E3015`.
- Evaluation order never changes a result (EVALUATION §4.1): forcing a value no longer flips a later
  `==`, and a check that observes `self` by identity runs once per identity.
- An `expect` captures its subject's check findings and fails on any poisoned read, the same in both
  test orders. A hard error's finding carries its check name and, at a `where`, the field path.
- A language-server pass overlapping a first file read could publish a stale diagnostic (a workspace
  first-read race since 2026-09-29): first reads are now marked pending and a refresh waits for them.
- Every Go, C++ and TS reader agrees on 199 decoder cases. TS now writes Go's and C++'s bytes for
  unknown members and cases (`unknown value <wire>`, `unknown case <tag>`), `missing`, `null`, a
  non-canonical integer key (`expected a canonical decimal integer key`), a `-0` key, `$retired`,
  `@json(pairs:)` slots, `expected a number that fits Float32` and `unknown bits 0x<hex>`. It also
  refuses duplicate ids of a keyed list and a bits integer above 2^63-1, as Go and C++ do. A member
  under key `k` is `<parent>.<k>` in every target, an empty key included (`$.m.`).
- Edit: `Editable` and `Apply` now agree (a 48,550-verdict walk found 76 mismatches and 98 internal
  errors, all ruled). Section "For config-studio" below lists the visible changes.
- `canon test` now reports `E3102` (repeated `@codes` code) and `E6004` (refused stable amendment)
  that `expect package passes` alone would have hidden.

## New: `expect package`

```
expect package [{ name: value, … }] passes | fails … | warns …
```

It builds the test's own package as stages A-D of `canon check` do. Each name is a top-level `let`
(public or `local`) of the test's package, and its value (any expression of the let's type, reading the
test's values and locals) replaces the let in a fresh world; every other let and const is evaluated
afresh, so derived values follow. The `expect` judges what `check` says of that world: instance checks,
package checks, verification. No emit, vector, lock or view check runs. `expect package passes` with no
braces judges the unchanged package. Errors: `E5006` `notLet`, `otherPackage`, `twice`; `E5004`
`package` and `packageCheck` name the checks that apply; an unknown name is `E2102`. A substituted value
that violates its type is a compile error. Consts and layers cannot be substituted. Worked example:
`examples/features/pkgchecks` (with its `expected/tests.txt`); `canon guide` has the recipe.

**Recipe for Resource's `…Problems` workarounds.** Package checks ran in no test, so Resource wrote
each rule as a `…Problems(rows)` fn that its package `check` loops over, and tested the fn. Keep the
check and test it through the world:

1. Leave the `check { for p in craftingLevelProblems(craftingLevels) { fail(craftingLevels, p) } }`
   block where it is.
2. In the test, replace `expect craftingLevelProblems(X) == [msgs]` by a substitution and the message
   the check fails with: `expect package { craftingLevels: X } fails "…msg…"`. `expect package passes`
   replaces `expect …Problems(rows) == []`.
3. Where the old test compared a list of two messages, write one `expect package` per message, as the
   diff below does for `persistedIds`.
4. Run `canon fmt`: it puts the braces over several lines.

The worked example on a copy of Resource (`n5-formatted.patch`, after `canon fmt`), for
`Config/items/catalog/craftingTests.canon`:

```
 test "a level index listed twice" {
   let l = craftingLevels.filter(x => x.index != none)[0]
-  expect craftingLevelProblems(craftingLevels + [l]) ==
-    ["level index {l.index} is listed twice (crafting.level-unique)"]
+  expect package {
+    craftingLevels: craftingLevels + [l]
+  } fails "level index 0 is listed twice (crafting.level-unique)"
 }
```

and for `Config/progression/persistedIdsTests.canon` (three tests, one shown):

```
 test "achievement rows and AchievementId agree both ways" {
   let rows = achievements
-  expect achievementIdProblems(rows) == []
-  expect achievementIdProblems(rows[1..]) ==
-    ["AchievementId ACHIEVEMENT_1 has no achievement row: retire it"]
+  expect package passes
+  expect package {
+    achievements: rows[1..]
+  } fails "AchievementId ACHIEVEMENT_1 has no achievement row: retire it"
```

On the copy the 4 rewritten tests pass, and fail with "got: no finding" when the check they guard is
removed; `canon test` counts are unchanged (782 passed), at about +4% wall time. A message that
interpolates (`{l.index}`) is written with its value (`0`) in the `fails` text.

## New: kept dependent maps, and amend paths into dependent maps

A dependent map `{k in c: T(k)}` whose value reads only `k` (and the binders of dependent maps inside
it) keeps its type at every read, and a literal typed against it binds `k` per key: `==`, `!=` and
`union` with a literal judge each value against `T(key)` (`E3802`), stored or not (408). A dependent
map whose value reads an earlier field or a parameter still reads as its static view, and `E3804` stays
there. An amend path enters any dependent map: `[k]` and `[#n]` name its entries, and the literal at the
path binds `x` to `k` and is judged against `T(k)` (409). `E1905` is no longer given for it.

## For config-studio (edit and workspace)

- Edit errors name display paths, never an absolute or temporary name. A failed rollback is a kept
  journal that wraps `ErrJournal` (`ErrProject` at the API), so `Open` fails as for any journal it
  keeps (416).
- An edit takes exclusively every package whose static read set holds a file it writes or a listing it
  changes (417).
- `Editable` promises what `Apply` does; the stricter side won. Reasons: `computed` for a Set or Reset
  of a `load(…)`, `mk()` or spread line (the Undo cannot write it back); `order` for a whole-collection
  Set ordered by file paths; `layer` for a path below a `load(…)` amendment, an AddEntry that needs a
  new amendment line under an inactive layer, a Remove of a line that re-values a base key, and a Reset
  of a field with no default inside a layer-only entry; `layered` for a user op on a path another
  active layer amends, including stacked Sets under `[dev, lx]`. Every `ErrInternal` on a promised edit
  became a working edit or the refusal the spec names, including a Set that drops a map key holding a
  layer line.
- Quoted or qualified amend keys (`byC[Color.green]`, ``byWord[`if`]``) are canonicalised in the Undo
  check; an allowed edit was refused before.
- A name a client reports in `workspace/didChangeWatchedFiles`, and each file a stale-revision error
  names, is read again whatever its stamp. A notification that fails to decode is returned as an error
  to the client.

## What stays owed

verdict. Grouped:

    change (storage `f_`, `Data::<fn>`, `<Class>_<fn>`, the conformance fields); a fourth hint for a

  - MSVC at scale is a documented limit (CODEGEN §9).
- **Checker, evaluation, tests.**
  - The checker's `kept` memo is never pruned across a Recheck lineage.
  - Dependent values: unstored dependent record literals are judged only where stored; a renamed binder
    walks an entry twice after a `union`; a finding on an unstored kept-map literal has no related

  - A literal built by a `where` that only stage B runs is judged free (EVALUATION §12.1 gap); a test
