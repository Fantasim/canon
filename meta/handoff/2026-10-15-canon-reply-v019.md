## Upgrade notes

- **Go enums without `@codes`** now have `MarshalText`/`UnmarshalText`: `encoding/json`, XML and YAML
  write the wire name and read it back by name (values and map keys). The scan found no consumer
  encoding one.
- **Journal version 2:** a v0.1.8 binary refuses a dead v0.1.9 journal ("unknown version") until v0.1.9
  recovers it. Do not switch binaries on a tree an interrupted edit left.
- **Edits write `` `in` `` where they wrote `Leg.in`**; both stay valid.
- **Case-only `out` renames now apply:** commit them with `git mv`.
- **Dot-prefixed `.canon` files** are no sources; none is tracked in Sovereign.
- **New findings that may appear:** `E3706`, `E8152` `dirCase`, `W8031`, `W1912`, `E1138`. The Resource
  dry run (Resource `350d0ed9`) found none: 0 errors, 0 warnings, 105 packages, 643 tests, every
  pre-push step green with both binaries.
- **Source:** regenerate `Engine/Resource/Generated/progression/recordbook.gen.h` after the bump: its
  two baked id enums gain the id comments and deleted `to_json`/`from_json`. Nothing in the dry-run copy
  used nlohmann on them.
- **Windows** keeps size + mtime in the refresh.

## Bench numbers (A = v0.1.8, B = 0.1.9; shared machine, loads in the log)

- **Refresh p95** (Evaluate + Value after an edit): median A 0.806 s, B 0.824 s, B/A 1.02, no
  regression. By ADR-0021 §6's fixed rule (baseline above 400 ms) the target is **1050 ms**. The
  baseline was measured partly at load 20-23; the one equal-load pair (load ~5) gave A 0.478 s, B
  0.623 s. Edit and Evaluate p95 miss their targets on both trees, as v0.1.5 and v0.1.6 recorded.
- **LSP publish p95:** median A 631 ms, B 624 ms, no regression; both miss 500 ms at load ~17.
