## For Louis

- **Frozen contract, your call (CLAUDE.md):** a map literal's symbolic key (`{ second: 1 }` against
  `{ref aa: Int}`) cannot be recorded in `Info`: `Info.Keys` is `map[syntax.Expr]` and a bare name is a
  `*syntax.Ident`, not an Expr, so IMPLEMENTATION-PLAN §4.7's "every identifier is in Defs, NameUses,
  Uses, Keys or Symbols" fails for it (go-to-definition and rename miss it; it happens at one level
  too). Fixing it changes `api/canon.go`'s frozen `Info` (a new map or a widened key type). Default if
  you say nothing: leave the contract as is in v0.3 and carry it to v0.4's plan.
- **Philosophy question: is a declared but inactive layer part of a valid project?** Today
  `canon check` type-checks every layer file but evaluates only the active ones (EVALUATION §9.1).
  So a layer broken by a hand edit or by git (an amend path gone: E1905, or a dependent value no
  longer fitting: E3802) stays invisible until someone activates it. In v0.3, edits re-check every
  declared layer, one at a time on the active stack (EDIT-ALLLAYERS; cost measured: about 18 ms per
  edit becomes about 63 ms with 10 layers, and about 271 ms with 50). Should `canon check` do the
  same, so that "check passes" means every layer evaluates? The cost per build is about one
  evaluation per layer. Default if you say nothing: `canon check` stays as it is in v0.3, and only
  edits cover inactive layers. One consequence to weigh: E19 refuses an edit for any error in its
  packages, so a layer that is already broken now blocks every edit of its packages (unless
  `AllowErrors`) while `canon check` still passes; the error names the layer.
