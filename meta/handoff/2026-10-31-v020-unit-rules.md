# v0.2 unit rules (ADR-0023 §0, §11.1): every builder reads this first

1. **Worktree.** You run in your own git worktree. First: `git merge --ff-only main` (fast-forward
   to main), then report the base SHA (`git rev-parse HEAD`). Never merge anything else.
2. **Forbidden:** `git stash`, `git checkout -- <path>`, `git reset`, `git commit`, `git rebase`,
   editing outside your unit's packages and granted files, editing spec/, DECISIONS.md, meta/,
   hand-editing a golden or a generated file. A need outside your packages: STOP and report it
   (the orchestrator grants the file or makes the fixup).
3. **The ADR is decision-complete.** Build exactly what meta/decisions/0023-v02-trust-release.md
   says. A better idea goes in your report as "proposal" and you still build the ADR's design.
   A small question the ADR does not answer: §0's fallback (the spec wins; else the reading that
   refuses more and writes less) and report the choice. A real gap (two readings, neither
   stricter): stop that part and report.
4. **Failing test first.** Write the section's tests first and show each fails on the UNCHANGED
   production files (copy the files aside and back with cp, never git). Paste the failing output.
   A test that does not fail: STOP and report: the ADR's reading was wrong. Exception: a test the
   ADR calls a pin passes by design; prove it can fail as its section says.
5. **Memory cap, every go test or probe**, exactly:
   `systemd-run --user --scope -q -p MemoryMax=3G -p MemorySwapMax=0 env GOTOOLCHAIN=local go test -timeout 300s ...`
   Temp dirs in /var/tmp. **Heavy runs** (eval package tests, `-race`, fuzz, C++/Go/TS golden
   compiles) are prefixed with the 2-slot semaphore: `/var/tmp/canon-v020/heavy.sh systemd-run ...`.
   Concurrency tests also at `GOMAXPROCS=2` and `4`.
6. **Do not run `make check`** (the orchestrator does). Do run `gofmt -l` and `go vet` on your
   packages.
7. **Goldens** only by `-update`. Read every golden diff and map each hunk to an ADR section in
   your report; a hunk no section explains: stop and report.
8. **Code doctrine:** .claude/rules/go.md (function ≤ 60 lines, ≤ 40 statements, nesting ≤ 3,
   named constants, no repeated string literal, doc.go/example_test.go, diagnostics only via
   `diag.<CODE>.At…`, rules cited in comments like `// EVALUATION.md §10.5`).
9. **Report back:** base SHA; files touched; the failing-first evidence; the VERIFY command log
   (tail); golden hunks mapped to ADR sections; gaps; any choice not in the ADR; what is
   unverified. Send your final report; do not stop without it.
