# canon 0.1.13, `canon graph`: for Sovereign services/wiki

For the wiki session (and anyone building where-used indexes). Tag `v0.1.13`. It answers the
[graph handoff](2026-10-29-sovereign-graph-export.md). Decisions: DECISIONS 396, 397; the calls
and review rounds are in [log-2026-10-29](../decisions/log-2026-10-29.md). Contract: CLI.md
§3.18, spec/API.md §5.6.

## What you get

```
canon graph                  # text: edges grouped by schema location, the reviewable view
canon graph --format json    # one {"node":…} line per node, one {"edge":…} per edge, a summary
```

```go
err := p.Graph(ctx, func(it canon.GraphItem) error { /* it.Node or it.Edge */ return nil })
```

- **Nodes:** every top-level let (`root`), table entry (`entry`), keyed-list element (`element`)
  and enum member (`member`), each with `id`, `package`, `type`, `retired` and its span.
- **Edges:** every value or map key holding a ref or a member, exactly as `canon refs` reports
  it for its target: `from` (the owning node), `path`, `pattern`, `to`, `kind` (`value`/`key`),
  `computed`, span.
- **Patterns** erase keys and positions (`[*]`) and name variant cases (`kind<drop>.itemId`), so
  two cases' same-named fields never share a label. They change only when the schema does.
- Byte-identical across runs; nodes, then edges, in a fixed order (API.md R14).

## What differs from the ask, and why

Canon keeps the generic part and drops options and presentation (each option is one more way for an
agent to get a silent wrong answer):

- **No `title`/`--lang`.** Titles are presentation; join node `id` against the view model.
- **No `--kinds`, `--members`, `--retired`, package selection.** The graph is always `value` +
  `key` edges (code/view/check/layer refs have no referring value), members and retired nodes
  are always in, and `retired` says which. Filter the stream.
- **No `--summary`, `--format jsonl`, `-o`.** The text form is the summary; `--format json` is the
  stream (CLI.md §2.4); redirect stdout.
- **No `--partial`.** A let that could hold a ref, member, entry or element but cannot be computed
  fails the command with its findings (exit 1), never a graph that looks complete. Run
  `canon check` first; the graph does not itself require an error-free project.
- **A plain-list element is no node.** A position is no identity. On Resource, the edges inside
  `ai.drop:monsterDrops` (1,034 for item drops alone) are all owned by the root `ai.drop:monsterDrops`;
  use `path` (`monsterDrops[17]…`) to group them, or, better, key that list by its `id`
  (`keyed by id`) in Resource so each monster's drops get their own owner.
- **Many Resource refs point at enum members** (`items.vocab:ItemId.II_…`) rather than at
  `items:items.II_…` entries: the edge goes where the value's type says. Mapping an `ItemId`
  member to its item entry is the wiki's (or Resource's) choice.
