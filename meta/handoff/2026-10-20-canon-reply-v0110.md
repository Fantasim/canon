**Bug fixes:**
- An `@codes(Int)` member coded `INT64_MIN` wrote an enumerator g++ refused.
- Readers of another package's class skipped refs at nested positions, in Go and C++.
- A ref union inside a `@json(pairs)` element produced Go code that failed `go vet`.
- A C++ `data`/`types` class held a ref into another package's baked table as an unchecked string.
- An empty `@cpp(defines:)` prefix wrote nothing, silently.
- A `"*"` prefix was accepted.

## Upgrade notes

- **C++ public API: a ref into another package's baked table.** In a `data` or `types` C++ emit,
  such a ref is now that package's id enum (`::lib::ItemId`), as CODEGEN §5.8 always said. Getters,
  make hooks and containers change type. Unknown keys fail with `unknown value <key>`, as in Go.
- **Linking.** A C++ program using an enum's helpers links the enum package's `.gen.cpp`. Every build
  that links its imports already does.
- **New errors.** A C++ name that is a standard-library macro (`UINT32_MAX`, …) is now an error.
  Rename it for C++ with `@cpp(name:)`; the Canon name, the wire and the lock are unchanged.
- **Defines validation.** A define name that is a C++ keyword, a name §3.4 reserves (`std`,
  `canon`, …) or an identifier of the runtime headers (`Decoder`, `json`, …) is refused.
  `_`-uppercase and `__` names stay allowed.
- **`@cpp(defines:)` on a `local` declaration** is `E1118`.
