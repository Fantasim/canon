# Decisions log — 2026-10-08

## Go `types` mode, pulled forward from v0.2 (handoff 2026-10-08-sovereign-go-types-mode)

- **Louis: ASAP.** Sovereign's cutover is blocked on it: its Go services (admin, website,
  monitoring) must read the JSON files Canon renders through `@text` fns, the files the game reads,
  through Canon-generated Go, and sovcommon's hand-written readers (~10.5K lines) are deleted. Go
  `types` was one of the three modes DECISIONS 320 left unbuilt (E8019 `unbuilt`); it is now built
  to the spec CODEGEN.md §2.2 and §5.13 already give it (no new language rule), mirroring C++.
- **What is built is the spec's shape, not the handoff's wish list.** The handoff asks for:
  - a `Load<File>(path)` per `@text` file. Refused: a `@text` fn is a file, not API (DECISIONS
    300). A `@text` JSON file is written so that `load` at the result type gives the value back
    (§2.9). The §5.13 public decoder `Decode<X>(raw []byte) (*X, error)` of the result's record
    therefore reads it, and the service does `os.ReadFile` + `Decode<X>`. The one condition is that
    the `@text` fn's result type is a public record (or variant) of a package with
    `emit go { mode: types }`; a list or map result is wrapped in a record.
  - refusal of unknown keys. Refused: §5.13 ignores them, so that a newer file is readable by an
    older binary. A wrong kind, a missing required key, an unknown enum member and an out-of-range
    number are refused with the JSON path, as asked.
  - a `$schema` fingerprint. Not in types mode (§5.13); `canon build --check` is the drift guard.
  - enums by name and code, and list `out` with copies: already the Go emit's shape (§5.2:
    `ParseX` reads the wire value, `String()` gives the Canon name, `XFromCode`/`Code()` with
    `@codes`; §2.1 copies). Confirmed in types mode.
- Builder: one opus `go-dev` on `internal/gen/go` plus the Go side of `internal/ir`'s stage-E
  rules (decode semantics are what goldens can miss). After review, the orchestrator syncs §2.2's
  "Three modes are not built" paragraph and adds a DECISIONS item (207).

## Second pass: the need behind each ask, Canon-native answers (Louis: "understand their need, do it cleanly, for every use case")

- **Go types (A).** Need: a Go runtime reads, with the right types, a file Canon renders (or a
  legacy file), without a second data set. The general answer is §5.13's decoder per public
  record. It serves every runtime and every file, not one generated `Load<File>` per `@text` file.
  The guide now says so (a doc gap made the ask look necessary).
- **Gated files (1).** Need: a system that is off must not ship its file (a client would carry
  unreleased data). An optional result as a maybe-file is the general typed answer. The cleanest
  complete rule would also remove a file that the package's previous `canon.outputs` owns and this
  build no longer writes (a renamed or removed `@text` file lingers today too); the precedent is
  the `.canon-text` migration deletion. Louis approved it ("auto delete is the best; they can
  regenerate it"): 336 removes a listed file the build no longer writes.
- **First-wins merge (2).** The loop is legitimate Canon, so its 40x cliff is fixed. The deeper
  gap: lists have `union` (receiver first, then what is new) but maps have none, so a merge of
  N tables needs a loop or `groupBy`+`[0]`. Proposed for v0.2: map `union` with the list's
  semantics, translated by every generator (too wide for v0.1.3).
- **Flag headers (3).** Need: Canon must know which systems are on, and so must C++. Reading
  `Sys_*.h` back makes Canon parse a preprocessor (no `load.defines` change: it reads constants,
  by spec). Canon-native: the flags live in Canon (`const`/`let` Bool) and Canon renders the
  header the C++ build includes (`@text("Sys_Features.h")`, a `String` fn writing `#define`
  lines). One source of truth, no parsing. Advice to Sovereign plus a guide recipe; no compiler
  change.
- **Edit memory (4)** and **literal spelling (5)**: general fixes as planned.
- **Map `union` pulled into v0.1.3 (338).** The "too wide, every generator" estimate was wrong:
  collection methods are never translated (CONFORMANCE.md §2.2), so it is checker + evaluator only.
- **Spec gap (map `union` review): a literal against a dependent map.** STDLIB §6/§1.2 and TYPES
  §11.5/§7.5 did not say what type a map literal takes as `union`'s argument, or as `==`'s other
  operand, when the receiver is a dependent map `{x in c: T(x)}`. Implemented: the static view
  `{ref c: T}`, which crashed `canon check` (ICE, IdentExpr) for a parameterized `T`; the `==` path
  was already broken before 338. Decided: the literal takes the dependent type itself, so each value
  is checked against `T(its key)`, as §11.5 says for that map's own literals. Recorded in 338.
- **336 review FAIL (2 critical): removal trusted every listed line.** A marked `canon.outputs`
  with an extra line made the build delete another package's source, `project.canon` or a
  hand-written file. Rulings: a listed path is removed only where a text file could be (own
  marker, not a run input, portable name, no emit output or other package's listing, no canon
  marker or `$schema`); cross-target `written` is computed over every emit; a case-only rename
  removes the old name only when `os.SameFile` says it is another file. WIRE §8.5 and 327 synced.
- **337 review FAIL (3 critical, spelling only):** repair path, dependent-typed Sources and lock-held values lost spellings. Ruled: only a value that is itself a literal token at its position keeps its spelling (a computed one, index or match arm, is canonical).
- **Go types landed (builder report).** Decode speed: ~110 ms/MB (encoding/json per scalar, the
  data-mode reading path; ~2.7 s for propItem's 25 MB, extrapolated). Fine at service boot; a
  token-streaming reader for data and types loaders is owed (perf). Open gaps logged, not blocking:
  an `@json(inline)` field with a default needs its tag in both C++ and Go decoders (WIRE §5.4
  silent); duplicate JSON object keys are taken last (`load` gives E7104); depth limit 10,000.
- **338 narrowed after a second review FAIL.** Typing a map literal by a dependent map was sound
  only for declared receivers; the rebuild from static views invented dependent types (false E3802,
  an `L(o)` that crashed), and map-valued dependent maps still crashed. For v0.1.3: `union` on a map
  whose value depends on its key, and `==`/`!=` of such a map against a non-empty literal (an ICE
  at HEAD), are E3804. Owed v0.2: keep dependent types through static typing.
- **337 PASS** (third round). A removed map entry's key comes back canonical: an AddEntry path key is a value (E25); stated in 337.
- **335 review FAIL (2 critical).** A field named `big`/`utf8` crashed the build (imports missing
  from the escape set); repeated JSON keys built maps with twice the same key. Rulings: a Go
  public decoder applies WIRE §3.1/§3.2's byte rules (it is the parser); no `math/big` in
  generated code (Duration decided by digit counts, linear); `utf8` joins §3.4's escaped imports;
  the error form stays per language (`<GoType>: $.<path>: <text>`); only a public record/variant
  `@text` result is readable by a runtime. CODEGEN §3.4, §5.13 and WIRE §8.5's sample synced.
- **338 round 3 FAIL: the root is older than 338.** A literal typed against a dependent value's static view outside a dependent field crashed the evaluator (`==`, lists, `if`, `union`). Ruled the general fix: E3804 (op "a literal"), TYPES §11.4 sentence; `union` refused on any map whose type mentions a key binder; workaround stated (declared field, or a `var` + `m[k] = v`).
- **Edit memory (item 4).** Leak: every op's analysis stayed alive through `applier.named`
  (`rootRef` held `*check.Package`); now paths only. Plus the edit adopts `format.Rewrite`'s
  fixed-point verdict on the next op's tree (DECISIONS 258 respected: bytes compared first). 170K
  lines / 36 ops: > 3 GB → ~1.5 GB RSS; 80K: 2.7 GB → 0.6 GB. Owed: time is ops × full analysis
  (API.md E1 by design; batching independent ops or incremental analysis is a v0.2 question);
  FMT's whole-file judgement holds the rest of the peak (per-item judgement, or the on-disk cache).
- **E3305 duplicated on an untyped map literal inside an if/list/in-list** (outer and inner brace): pre-existing cascade, never a crash; out of v0.1.3 scope, recorded in E3305_3, owed. bind.go mirrors eval's binder logic (check cannot import eval): a drift risk to watch; a shared home in internal/types is owed.
- **338 round 4 FAIL: the evaluator rebound a dependent map's binder to a nested map's keys**
  (`{x in evs: {String: L(x)}}` bound x to "k"; older than 338), and bind.go's copy had drifted.
  Ruled: a binder is bound only by its own dependent map's keys (TYPES §11.5); one copy of the
  binding walks in internal/types for check and eval; `argsInError` reverted (it hid independent
  errors). An amend path into a dependent map being E1905 is a separate, owed gap.
- **338 round 5 (strict binder):** a non-empty record literal compared with a dependent-map PARAMETER in a fn body (`m == { a: {} }`) is now E3804 (HEAD evaluated it): the strict rule never guesses a binder from a static view, since a guess can bind another collection's key. Workaround: a let declared with the dependent type.
- **Go predeclared imports:** alias `<name>pkg` (registered as an import), not `<name>_`, which collided with the escape of a field `max`.
- **336 PASS** (round 3). Owed (DECISIONS 326, unchanged): on a case-insensitive FS, renaming a @text file by case while changing its content is E8001 (ownership compares display paths case-sensitively).
