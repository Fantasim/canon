  changes static identity and which every backend strips. A new wrapper would need a case in
  every exhaustive type switch, and a missed case would fail silently. The unit audits the
  consumers of `*types.Refined` before settling on the flag.
- **`E3502` widened.** Before: only a ref inside a live table entry (`internal/verify/rejudge.go`,
  `sc.entry != ""`). A ref to a retired entry in a plain `let` passed, while `E3506` applied to
  every stored value. The two now apply alike. Outside a retired entry, such a ref is new use.
- **Messages name the way out.** `E3502` and `E3506` say "only a retired entry or a past … may".
  The telemetry agent hit `E3506` and had no hint that history could be typed.
- **DECISIONS 305, every ban has a reason and a way out.** Added as a DOCTRINE §2 line and a
  spec-reviewer check (WARN).
- **Numbering.** The ban rule took 305, so the designs drafted as 305-307 become 306 (enum
  reflection through a type function), 307 (optional type-function argument) and 308 (encoders).
- **306, the name `typeName`, unqualified.** `E.name` would reserve a member name that real enums
  use (`enum SortKey { name, date }`). Qualified text exists already as the canonical type text
  (DECISIONS 78) where it is needed.
- **307, a `none` argument computes `Never`.** The alternative was to require `!`. With `Never`,
  a role on a column without a vocabulary fails at the data (`E3801`/`E3802`), not at the
  declaration (`E4001`). The design review had blamed the ref for `Member(column.values)`. The
  design agent found that paths through refs are already legal (TYPES §6.6,
  `E8019_58.txtar`); the blocker is that `Column.values` is optional.
- **Spec gap kept open.** VIEWMODEL J13/J14 do not say how the studio follows a driver path
  through a ref; it predates 307 (`Target(g.goal)`). It goes to "Still open", not fixed here.
- **308, a `@text` fn returns a typed value written as JSON.** The design agent proposed it
  instead of a `json(x)` stdlib fn, which would need `eval` to reach `wire` (IMPLEMENTATION-PLAN §3)
  or a second JSON dialect. A text output may thus be bare JSON. This is not a breach of GEN-06:
  that rule is about data files, which generated loaders read and fingerprint, and a text output
  is neither. Noted for Louis. Telemetry's catalog moves to `format: 3` (a tombstone becomes a
  tagged variant), handed off to Source. JSON embedded inside other text (JSON lines, JSON inside
  SQL) stays impossible until `wire`'s encoder sits below `eval`.

## 304 implementation rulings (unit 1 report)

- **`past` before any type, not only names.** Unit 1 found that GRAMMAR's first `pastType`
  (`"past" (namedType | refType)`) made `past [K]` a syntax error ("expected topDecl; found ["),
  while TYPES §8.4 promised `E3024` for any other type. `past [GrantKind]` for `[past GrantKind]`
  is the likeliest mistake, so it gets the clear finding: `pastType = "past" primType`, except
  before `(`, which stays a type function named `past`.
- **`Kind(V)` and a case type `V.c` are refused (`E3024`).** §8.4 says "names an enum or a
  variant". A variant kind is an enum only by construction (§8.3), and a case type is a part of
  a variant, not a variant.
- **Syntax shape: a `Past` token on `NamedType`/`RefType`, not a new node** (unit 1's choice, kept
  and extended to every type node the new grammar allows). IMPLEMENTATION-PLAN §4.1 says the owner
  adds no node outside its list, and consumers that switch on syntax types keep working.
- **Views treat `past X` as `X`** (`views/shape` `sameRefinements` ignores `Past`). 304 says the
  two are statically the same type, and G8/G21 compare static types.
- **The ERRORS.md count sentence** went from 302/481 to 303/483; diaggen refuses a stale count.
