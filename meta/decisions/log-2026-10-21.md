# Decision log — 2026-10-21 (v0.1.11, optimisable emits)

Ask: Scripts' [ids-gen-optimisable](../../../../Scripts/meta/handoffs/2026-10-21-canon-ids-gen-optimisable.md):
Resource's `header/ids/ids.gen.cpp` (1 MB, 33,600 strings in initializer lists inside one
`Build()`) went past 15 GB under `clang++ -O3 -g`; Scripts compiles it at `-O0` as a stopgap.

## Measurement (real Resource build, 0.1.10)

| Target | Units | Result |
|---|---|---|
| C++ `-O3 -g` (clang 21) | 112 | `ids` killed at the 4 GB cap; `telemetry/feeds` 50 s (24k-line `Build`); all others < 850 MB |
| Go (1.25) | 132 | all build; `text/vocab` 1.27 GB / 22.5 s (23k-line enum switches) |
| TS (tsc 5.0, 7.0) | 52 | all < 440 MB, ~2 s; nothing to do |

## Decisions

- **392** (gen/cpp): bulk arrays at namespace scope, column fill, `Build<N>` parts, header list
  constants over `detail::k<NAME>Elems`, a literal union over a large enum checks through
  `<E>FromWire`. Thresholds: 8 elements (`bulkMinElems`, small goldens unchanged), ~1,000 lines
  per part (`bakedPartLines`: bounds optimiser time; memory is bounded by the arrays). Strings in
  arrays are sized `std::string_view("…", len)`: plain literals hit clang's constexpr step limit
  on 33,600 names. A make-hook argument that is a literal is passed directly, not through a
  local (clang's debug-info assignment tracking on 3,000-line functions full of locals cost 2 GB).
  Result: `ids` 219 MB / 2.3 s; feeds 491 MB / 14.6 s; progression 378 MB / 10 s.
- **393** (gen/go): enum methods read `enum<Role>_<Type>` tables, one shape for every size (a
  threshold would mean two shapes). Behaviour dump on TextId byte-identical (88,816 lines);
  lookups slower (String 215 -> 322 ns, FromCode 34 -> 60 ns), no allocation: accepted.
- **394**: the real-data release gate (why 0.1.10 missed this: compile tests at `-O1` or
  `-fsyntax-only` on small fixtures; the one scale test timed enum helpers only, no RSS).

## Spec gaps decided

- CODEGEN §2.7, §3.4 (`slices`), §3.5, §5.1, §5.2, §7.3 synced to 392/393.
- Equal wires in one enum (`a = "x", b = "x"`): WIRE.md §5.3 and TYPES.md §8.1 assume unique
  wires; the checker accepts them, so round-tripping the later member returns the first. Go now
  matches C++ (first declared wins, 383). Open: whether equal wires should be an error (v0.2).

## Owed (not in v0.1.11)

- gen/go: `buildX` grows with rows (`progression` 6-10 s); `codesIndex` (fns.go),
  `inputEnumBody` (inputs.go), `readBits` (convert.go) grow with members.
- gen/cpp: `@cpp(defines:)` wraps macro names met only inside string literals; a nested
  foreign-record block in `monitoring` can still reach ~1,700 lines (not split inside blocks);
  clang-cl/MSVC of the array forms unverified.
- Retired members in the C++/Go enum API ([handoff](../handoff/2026-10-21-sovereign-cpp-retired.md)): next.
- gen/cpp: an opened enum (`types` mode) defines one `inline const E E::x{...}` per member in its
  header: 60,000 members means 60,000 dynamic initialisers in every including TU.
- gen/cpp: a JSON member name or variant tag holding a NUL is cut by the runtime's `const char*`
  decoder API (`dec.Required/Optional/Step/String`); needs `string_view` overloads in
  `canon_runtime_json.h` (version guard) or a check refusing NUL in wire names. Decide in v0.2.

## Review rounds

- gen/cpp follow-ups (same unit): embedded NUL kept on every data path (sized
  literal only when the text holds a NUL, goldens unchanged); enum/id/defines tables of 1,024+
  entries use sized `string_view` (plain literals hit clang's constexpr step limit at 60k).
- gen/cpp, round 1 FAIL: `kBulk<N>`/`Build<N>`/`k<NAME>Elems` not reserved (a record `Build0`
  miscompiled with no finding) -> reserved in the C++ name plan, `E8005_67..69`; nested lists and
  maps, define-value and dependent lists still inline -> hoisted; NUL on template text and case
  wires -> sized. DECISIONS 392 now cites §3.5/§5.13 (not §5.9: column fill is §7.3's).
- gen/go, round 1 PASS with conditions: spec sync, equal-wire test, zero-member enum vet failure
  (pre-existing), kind enums at scale, no duplicate wires table.
