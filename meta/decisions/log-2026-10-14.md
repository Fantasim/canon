  `tidCode` (`events/vocab/display/display.canon:100`, copies in `recordbook/boards.canon:120`,

  (to decide after the lambda numbers).
- **Owed levers, ranked:** lambda calls copy their captures (~19% of allocation); `value.Prov`
  slimming/interning (26% of live heap); per-package parallelism of stages A, C/D, E (the only
  big wall-time lever; the evaluator's memo, depth and budget must split per package first).
- **Lambda captures landed (4cca5d42).** Closures share a read-only capture list; frames bind
  four names in place; an unnamed frame reuses its caller's stack. Review PASS after a test pinned

## Robustness before speed (Louis, 2026-10-14) — documented for later, nothing started

- **Rule (Louis):** "I don't want to do optimization if it's risking the robustness of Canon."
  Allowed: changes proven byte-identical by goldens (allocation, data structures), consumer-side
  fixes (Resource `tidCode`), host-side work (studio preloading). Parked until Louis's explicit
  go: per-entry/per-field re-check, the on-disk cache, per-package parallelism (races are
  intermittent; it also touches the eval memo).
- **Audit of existing reuse** (read-only, 18 mechanisms): no confirmed wrong-answer bug. One
  real gap: **refresh trusts size + mtime** (`internal/workspace/refresh.go` `ifStale`,
  `snapfs.go` `stampOf`; API.md S1 says exactly that). A same-size file replaced with its old
  mtime kept (`cp -p`, `rsync -t`, `tar x`, `touch -r`) stays stale in a long-running Project
  (studio, LSP, repeated API calls) until another change; one-shot CLI runs and Canon's own edits
  are safe. Planned fix: add ctime + inode (+ dev) to the stamp (build-tagged: `Stat_t.Ctim` on
  Linux, `Ctimespec` on darwin/BSD, today's behaviour elsewhere), a test that fails on the old
  code, and S1 reworded (DECISIONS item). ~1 day. Test-guarded only, no runtime oracle: the
  edit verdict adoption (ADR-0019, rests on M5) and the eval memo replay (ADR-0011; parallelism
  and `Prov` slimming must pass the cold-vs-incremental gate).
- **On-disk cache (CLI.md §2.7), safe design if ever built:** per package, store the findings
  with the recorded read set (every file, stat and listing the check consulted, with its
  SHA-256), the way `internal/load/memo.go` replays and compares every file-system call; reuse
  only after re-hashing every read; unknown reads = always re-check. Compiler identity = hash of
  the binary (covers `dev` builds). Temp-file + rename writes, per-entry checksum and format
  version, any doubt = miss. CI and `--verify-cache` compare cached against full check
  byte-for-byte. Residual risk: a read bypassing the recorder. ~1-2 days. Helps CLI, agents,
  Scripts, CI; does **not** help studio Save or tables (an `items` edit misses for all 31
  packages; tables need values, not findings).
