## DECISIONS 293: baked C++ lookups with scalar results are constexpr

Passage: CODEGEN §7.1 "The header declares; `.gen.cpp` defines loaders, accessors, lookup tables,
baked data …"; L-0111 d.1.8 needs `static_assert`, `if constexpr` and template arguments on event
metadata. Choice: only `baked`, only package-level precomputed or lookup fns, only constexpr-scalar
results (integers, Float, Bool, String as `string_view`, Duration, enums, table ids). Lists,
records and optionals keep the split, so the header does not grow data structures. Indexing is by
ordinal (declaration position), never by an enum's code, since `@codes` enums have gaps.

## DECISIONS 294: the text target

Passage: GRAMMAR §8 (targets go, cpp, ts, json, view); L-0111 d.1.3 (four `.sql` files and
`catalog.json` format 1 as build-time export fns). Rejected: a JSON `$fns` extractor in Source
(it lives outside Canon, `build --check` cannot see drift, and it needs an emitted value). Choice:
`emit text { out: dir }` plus `@text("file")` on public, parameterless, String export fns, bytes
written verbatim. A text file has no marker, so ownership is a `.canon-text` file per directory
(marker + names); E8001 otherwise, `--adopt` to take a hand-written file over. New code E8021
(check) and E8009 `textEmpty`.

## Louis: elegance over legacy shapes

Louis: Resource's integration (vocab JSON + schema, define headers, xmacros, telemetry's
gen_views.py outputs) is the pain Canon removes; it is never the model. The telemetry dry run
(TE) designs the package the Canon-native way and does not reproduce gen_views.py quirks byte for
byte (FROZEN_EVENT_ORDER, two banners, `CAST(n AS SMALLINT)`, the hash-of-every-view catalog).
Its handoff lists where Canon's outputs differ from today's files, and Source refactors its
integration (L-0111 d.1.7's byte-for-byte proof is Source's to revise; this ruling is the input).
When a generator cannot write an elegant construct, the generator is the gap, never the example.
