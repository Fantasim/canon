# Decision log — 2026-10-29 (v0.1.13, `canon graph`)

Ask: Sovereign's [graph handoff](../handoff/2026-10-29-sovereign-graph-export.md): the whole
reference graph from one analysis, for a generated wiki; `canon refs` costs about 40 s per target
on Resource (measured here: 39.8 s, 2.1 GB).

## Decisions

- **396**: `Project.Graph` / `canon graph`. Kept from the ask: one analysis, streamed nodes then
  value/key edges, owner, path, pattern, computed, spans, fail rather than look complete, parity
  with `refs`. Dropped as knobs or presentation (canon never bends: fewer knobs, fewer agent
  mistakes): titles and `Lang` (join the view model by node id), `Kinds` (code/view/check/layer
  refs have no referring value), `Members`, `Retired` and package filters (always included,
  flagged; the consumer filters), `--partial`, `-o`, `--format jsonl`, `--summary` (the text form
  of §2.4 is the summary; `--format json` is the stream).
- **Nodes are `Refs` targets plus roots, at their own identity only.** A plain-list element is no
  node (a position is no identity): on Resource, `ai.drop:monsterDrops` is a plain list, so its
  1,034 edges are owned by the root. Resource can key it by `id` (reply).
- **397**: the pattern is built from steps, `[*]` for every key/index/entry, and names the
  variant case (`<c>` after the root and every step but the last), so two cases' same-named
  fields never share a label.

## Spec gaps decided

- Spec review round 1 (`6f995827`): copies are no nodes; R15 covers lets that could hold nodes,
  keys not computed, error-typed lets; the error is a `*PathError` (`ErrNoValue`) naming the first
  failing let in (package, name) order; R8 tie order written down as `refOrder` has it (value,
  key, code, view, check, layer; not the API's string order); `<c>` never after a key edge's last
  step; a graph of a project with findings holds what was computed (an `E3501` ref is no edge);
  CLI sample sorted by bytes; IMPLEMENTATION-PLAN §8.1 row, README row, S8, P10.
- Builder gaps (`ed859711`): a collection-valued let's re-adopted entries are nodes (315); an
  identity met at several paths takes the first that stays in its source tree, else the first in
  walk order.
- Code review round 1 (`9b20eb12`): entries of a collection that belongs to no let or field
  (optional or case field, nested list, map value) are nodes where met; `load.defines` entries
  only under their own let; one node per identity (a duplicate is an internal error).
- `GraphNode.Type` empty: unreachable (an error-typed let fails under R15); not specified further.

## Measured on Resource (scratch copy, `sov-v0112` tree)

`canon check` 36-45 s, 1.9 GB. `canon graph`: 105,688 nodes, 187,297 edges, 1,059 groups; 31 s
alone (42 s with other jobs running), 2.6 GB; JSON 71 MB, byte-identical across two runs. Parity
with `Refs`: 9 sampled targets here, 231 in the code review (incl. `ModelType.MODELTYPE_MESH`,
8,817 edges), all identical.

## Owed

- TYPES.md §10.2: an optional collection field (`[T] keyed by k?`) seems to get no field
  collection (eval's `collectionOf` takes `t.Base()` without unwrapping the optional); check
  whether its entries should keep the field's identity (Resource `world:paidWorldsTable`).
- R7: a level-1 ref rebound by a spread (`{ ...arena, boss: 1 }`) is listed only as a `code` ref,
  so it is a value edge of no target in the graph too.
- Graph peak heap is about 2 KB per edge (the walk's per-child segs); fine at 200k edges, look
  before the 1M scale.
- `internal/edit` is 114 files, 21k lines; split candidates when next touched.
