# Decision log — 2026-10-22 (v0.1.12, retired members in the enum API)

Ask: Sovereign's [retired-member handoff](../handoff/2026-10-21-sovereign-cpp-retired.md): the
runtime define table, built from the generated C++ id enums, must not resolve a retired id by
name, and no generated API exposed retiredness (`kItemIdMembers` 7,306 members, 7,244 live).

## Decisions

- **395**: both forms the handoff offers, in every target, not only C++ `@codes` and table-id
  enums. Rule: beside every name or wire lookup a retired lookup (Go `Retired()`, C++
  `IsRetired`), beside every members list a live list (`<E>LiveMembers`, `k<E>LiveMembers`).
  Reason: one rule everywhere is less for an agent to get wrong than a per-target, per-kind
  list (canon never bends to one consumer's subset). TS gets the live list only: its enum API is
  data constants, with no per-value lookup functions besides the open enum's.
- A value that is no member (a C++ `static_cast`, an open enum's unknown wire) is not retired:
  it is unknown, which `IsKnown`/`FromWire` already say.

## Spec gaps decided

- CODEGEN §5.2, §5.3 synced to 395 (`2c2488c2`).

## Collision found: a consumer's own `isRetired`

- The new C++ `IsRetired` overload is `E8005` against an `export fn isRetired(e: E)` over an
  enum of the same package. Sovereign has one: `Resource/Config/telemetry/cpp.canon:51`,
  `isRetired(t: EventType)` = `events.get(t) == none` (no layout), not "declared retired": a
  same-signature C++ redefinition with another meaning, so `E8005` is right and the name stays
  `IsRetired` (the handoff's). Upgrade note: Sovereign renames that fn (e.g. `isUnregistered`)
  with the pin bump. canon's `examples/telemetry` `isRetired` (= `e.retired`) is renamed in the
  example source; the generated `IsRetired` replaces it.
- The release gate (394) builds Sovereign's real tree, which has the collision: it runs on a
  scratch copy with that one rename, said so in the reply.

## Review round 1 (spec gaps decided)

- Two open-enum members on one wire: the live list follows the declarations (each member's own
  `retired`), in every target; `Retired()`/`IsRetired` on a value answers for the first
  declared member of its wire (383/393), since a value cannot tell the two apart. Go built its
  list through `Retired()` and kept a retired member; fixed to the declared flags.
- The `// …` remarks in CODEGEN §5.2's code blocks (`not retired (DECISIONS 395)`, `declaration
  order, …`) are annotations, never emitted: generated code cites no DECISIONS item.
- Round 2 accepted: `cppStdMacroNames` is split head (constants.go) / tail (constants_macros.go)
  to keep both the 500-line and 20% comment caps without dropping spec pointers. **Owed:** move
  the C++ macro lists to an embedded `internal/ir/text/` data file, one sorted unit.
