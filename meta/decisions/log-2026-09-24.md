## Chosen while resuming (build report and conform reviews)
Neither DECISIONS 201 nor CLI.md settles these; the strictest consistent reading is implemented.
- **`-q` on `canon build`** prints errors only (CLI.md §2.3): the output and lock listing is
  suppressed too, text and JSON; error findings and the summary stay (as DECISIONS 144).
- **`written` / `stale` counts include lock changes**, and a lock that `--check` finds out of date
  is listed with the `stale ` prefix (else `--check` exits 1 with `"stale":0`).
- **An `--adopt` output under `--check`** is reported and counted as stale: nothing is written.
- **Conform scope (CONFORMANCE §2.1 / E9008 vs EVALUATION §2.3):** vectors, E9008 and E9009 apply
  only to packages with a go, cpp or ts emit, since only a code emit translates a method; a
  json-only or view-only package has no translated method (and no conformance file, §7.1).
- **Float32 bound neighbours** are float32-adjacent (`math.Nextafter32`), reading 204's "adjacent
  representable values" in the parameter's type. **Float reads** keep §6.2's v−1, v, v+1 (204
  names bounds only).
- **E9009 (§6.5):** one finding per cut vector; the other vectors still run; the fn keeps none.
- **Precomputed method of self:** CONFORMANCE §2.2 wins: it is read like a field (its value is a
  constant of the receiver); 204's "a method of self" is read as a non-precomputed one.
- **Frozen eval interfaces:** conform's wiring (test-call recording, a vector-run mode) extends
  them additively under IMPLEMENTATION-PLAN §4's review rule (opus + spec-reviewer + ADR).
- **IR round 2 (202/203):** one `E8011` per declaration even when several derived names are
  invalid (its override problem if any, else the first derived name); 203's "one `E8005` per
  cause" holds across scopes, not only within one struct; `math` is planned only where gen/go
