# Decisions log — 2026-10-20

## ADR-0022 run (v0.1.10)

**S1: the `E8011 macro` row moved from MACRO's worktree into S1.**
- *Passages:* ADR-0022 §8.2 put the ERRORS.md row in MACRO's worktree, so that `make check` never
  sees an ERRORS.md edit before `internal/diag` is regenerated.
- *Choice:* S1 added the row, ran `diaggen` and the messages golden's `-update`, and bumped
  `catalogueMessages` (553 → 554). `make check` was green. Nothing in the row needed a builder.

**MACRO review, finding 1: parameters are verbatim positions.**
- *Passages:* ADR-0022 §7 Decision 1 says "every position the C++ name plan declares". DECISIONS
  388 says "a generated C++ name", and CODEGEN §3.4 says "in every position", listing parameters
  among the verbatim positions.
- *The problem:* the plan never declared lookup-method and precomputed-fn parameters, so
  `fn both(self, EOF: Bool)` passed `check` and broke g++.
- *Choice:* DECISIONS wins (DOCTRINE §2). Every non-translated export fn parameter goes through the
  identifier test, with no new `E8005` pairs.

**MACRO review, finding 2: "a getter derived as a macro" cannot occur.**
- *Why:* C++ getters are `Get` + UpperCamel or `<Name>Key(s)`, and no table entry has that shape.
- *Choice:* the test uses a baked table key `EOF` instead, which becomes an id enumerator.

**MACRO review, finding 3: `_IOFBF`, `_IOLBF` and `_IONBF` report `macro`, not `reserved`.**
- *Why:* they are in [cstdio.syn] and also match the `_` + upper-case rule.
- *Choice:* `macro` is checked first, because it is the more precise variant.

**MACRO open point: glibc's non-standard names.**
- *The problem:* under g++'s default `_GNU_SOURCE`, the same ten headers define about 287
  non-standard names, such as `EDQUOT`, `INT32_WIDTH`, `LC_MESSAGES`, `BYTE_ORDER`, `M_PIf` and
  `alloca`. Each breaks a header on Linux, with no finding.
- *Choice:* out of DECISIONS 388's two closed lists. Owed: a W8006 widening as its own DECISIONS
  item, not part of v0.1.10.
