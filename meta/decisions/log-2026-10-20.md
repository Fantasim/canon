# Decisions log — 2026-10-20

## ADR-0022 run (v0.1.10)

**S1: the `E8011 macro` row moved from MACRO's worktree into S1.**
- *Passages:* ADR-0022 §8.2 put the ERRORS.md row in MACRO's worktree, so that `make check` never
  sees an ERRORS.md edit before `internal/diag` is regenerated.
- *Choice:* S1 added the row, ran `diaggen` and the messages golden's `-update`, and bumped
  `catalogueMessages` (553 → 554). `make check` was green. Nothing in the row needed a builder.

**MACRO review, finding 1: parameters are verbatim positions.**
- *Passages:* ADR-0022 §7 Decision 1 says "every position the C++ name plan declares". DECISIONS
  388 says "a generated C++ name", and CODEGEN §3.4 says "in every position", listing parameters
  among the verbatim positions.
- *The problem:* the plan never declared lookup-method and precomputed-fn parameters, so
  `fn both(self, EOF: Bool)` passed `check` and broke g++.
- *Choice:* DECISIONS wins (DOCTRINE §2). Every non-translated export fn parameter goes through the
  identifier test, with no new `E8005` pairs.

**MACRO review, finding 2: "a getter derived as a macro" cannot occur.**
- *Why:* C++ getters are `Get` + UpperCamel or `<Name>Key(s)`, and no table entry has that shape.
- *Choice:* the test uses a baked table key `EOF` instead, which becomes an id enumerator.

**MACRO review, finding 3: `_IOFBF`, `_IOLBF` and `_IONBF` report `macro`, not `reserved`.**
- *Why:* they are in [cstdio.syn] and also match the `_` + upper-case rule.
- *Choice:* `macro` is checked first, because it is the more precise variant.

**MACRO open point: glibc's non-standard names.**
- *The problem:* under g++'s default `_GNU_SOURCE`, the same ten headers define about 287
  non-standard names, such as `EDQUOT`, `INT32_WIDTH`, `LC_MESSAGES`, `BYTE_ORDER`, `M_PIf` and
  `alloca`. Each breaks a header on Linux, with no finding.
- *Choice:* out of DECISIONS 388's two closed lists. Owed: a W8006 widening as its own DECISIONS
  item, not part of v0.1.10.

**HELPERS, gap 1: a table id's `ToWire`.**
- *Passages:* CODEGEN §5.3 said "inline `ToWire(StatusId)`". The amended §7.1 says the `.gen.cpp`
  defines "enum and id-enum lookups (`ToName`, `ToWire` …)". ADR-0022 §2 named closed and kind
  enums only.
- *Choice:* move it, under the generality rule: a large `baked` table must not put a per-key
  switch into every TU either. It becomes an array by position in the `.gen.cpp`. §5.3 and
  DECISIONS 383 now say so.

**HELPERS, gap 2: an opened `@codes` enum gets no `detail` ordinal trio.**
- *Why:* a class holding a `std::string` cannot have a C++17 `constexpr` ordinal.
- *Choice:* accepted. Its `FromCode` keeps local arrays.

**HELPERS found a pre-existing bug.**
- *The bug:* an `@codes(Int)` member coded `INT64_MIN` passes `check`, but the C++ enumerator is
  written with `%d`, and g++ rejects it under `-Werror`.
- *Choice:* fixed in HELPERS with `intLit` and a fixture case, because every known bug is fixed
  before release.

**HELPERS review rulings.**
- **Constants.** Overflow constants in `errors.go` move to `constants.go`, which has room since
  MACRO moved its variable blocks out. `gen/cpp/errors.go` keeps its format constants, by
  precedent.
- **Opened enums.** One sorted wire table per opened enum, in an unnamed namespace of the
  `.gen.cpp`, not four copies (the generality rule).
- **`INT64_MIN` in `#define` lines** goes to DEFINES.
- **Spec gaps.** The reviewer found that CODEGEN §2.7 did not state the header place of the
  `detail` ordinal block, nor the `.gen.cpp` order of enum and id-enum helpers. The orchestrator
  wrote both.

**TYPES review rulings.**
- **Criticals.** Both are fixed: an enum-keyed keyed list under a ref union did not compile in
  `data` mode, and another package's reader did not check a ref union.
- **A bug that predates the run.** That reader also skipped plain refs in map keys and values and
  in nested lists, against CODEGEN §2.8's "every position". It is fixed too, as a separate commit.
- **Optional elements.** `[ref T?]` and `[Pick?]` elements are checked when present, under the
  strictest reading. CODEGEN §5.8 now says so.
- **Unions over a `load.defines` ref** are not looked up at load, because no define table is
  emitted for them. This is documented in §5.8.
- **Friends.** A decoder that builds a default is befriended by the classes it writes; documented
  in §7.2. Building the default in `<P>Access` was weighed and refused: `Access` is defined after
  the decoders, which would mean reordering the `.gen.cpp` for no gain.
- **`@text` decoders** for results holding `[T?]` or `{K: V?}` go to GO, since `text_decoded.go`
  is shared by every target.
